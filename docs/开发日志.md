**IconServices 对「bundle 所在路径」缓存图标渲染结果，且该缓存键不含 bundle id、icns 文件名、inode、mtime。**

|---|---|---|

| 2 | icns **字节完全相同**（md5 `c1845a8a25`）的探针装到**不同路径** → 全部渲染完美 | IconTestA/B、IconProbeC、DaoPapersNEW 对照帧 |
| 3 | 换 bundle id → 渲染正常 | DaoPapersNEW |

### 被推翻的假设（记录以免重犯）

1. legacy 图层导致花屏 → 只差 legacy 层的两个 app 渲染逐项一致

### 抓图方法三坑（本轮各踩一次）

1. 整屏截图随机撕裂 → 斜向彩色条带，**视觉上极像「彩色噪点」**，曾追一个由抓图工具制造的假问题 → 必须用 `screencapture -x -R` 区域截图

3. 噪点数值判据不可靠（语音备忘录、HP 等高饱和正常图标被误判）→ 最终靠**肉眼对照同格位前后帧**

### 沙箱适配（重要，本轮踩了很多坑）

本机受限沙箱会拦截**删除**与部分系统调用，导致常规构建链路全线失败。已定位并绕过：

| 被拦截的操作 | 表现 | 解决方案 |
|---|---|---|
| `mkdir`（项目根下建目录） | RC=1 静默失败 | 改用 Python `os.makedirs`（脚本里封装为 `mkdirs()`） |
| 项目根下建**隐藏**目录 | RC=1（`.build` 建不出来） | 构建目录改用非隐藏名 `build/` |
| `cp` | RC=1 静默失败（内部 unlink 目标） | 改用 `shutil.copyfile`（封装为 `copy_to()`） |
| `chmod` / `touch` | 静默失败 | 改用 Python `os.chmod` / `os.utime` |
| **heredoc**（`cat > f <<EOF`） | **把脚本打断**（真凶！zsh 要往 $TMPDIR 落临时文件） | 改用 Python 写文件 |
| `iconutil` | `Failed to generate ICNS`（要写系统临时目录） | 自组装 icns（`scripts/build_icns.py`） |
| `codesign` | 要写 `.cstemp` 再改名 | 失败只告警不阻断（实测 ad-hoc 签名失效**不影响启动**） |
| `tempfile` 全域不可用 | Python 启动即报「无可用临时目录」 | 所有第三方工具改走不依赖 tempfile 的路径 |

**已修的隐蔽 bug**：PyObjC 的 `NSImage.drawInRect_fromRect_operation_fraction_` 重载会**丢掉源矩形**，
整张图画不出来（画布上只剩空白方块）。必须用单参数 `drawInRect_`。
→ 曾导致 `preview-icons.png` 里的图标全是白块。已在 `gen_preview.py` / `gen_compare_preview.py` 修复并注明。

## 2026-10-25 · 应用图标「换了但没生效」根因定位与修复 ✅

### 真正的根因：icns 容器 chunk 长度字段少写了 8 字节
`scripts/build_icns.py` 原来写 `struct.pack(">I", len(data))`（纯数据长度），
而 **Apple 规范要求 chunk 长度含 8 字节头**（type + length）。
→ 解析器读完第一个 chunk 就错位 8 字节，第二个 chunk 的 type 读成了 `IEND`
→ IconServices 判定整张 icns 非法 → **回退到「通用应用占位图标」**（纯灰方块）
→ 启动台渲染成彩色噪点、Dock 显示旧缓存、窗口代理图标不更新。

用系统 Calculator.icns 验算确认规范：
`8 + 35554 + 1693 + 788 + 12419 = 50462` = 文件总长 ✅

### 三个「假通过」的验收（我的方法论错误，教训最值钱）
| 验收方式 | 为什么不可信 |
|---|---|
| 自写 `build_icns.verify()` | 生成器与校验器用**同一套错误约定**，自己验自己当然通过 |
| 「系统 ImageIO 解析成功」 | ImageIO 只解了**第 0 帧**就返回成功；结构错位在第 2 个 chunk 才出现 |
| `iconForFile_(.icns)` 判灰 = 占位图 | **判据本身错**：系统 Calculator.icns 同样返回灰。macOS 对孤立 .icns 本来就不渲染内容 |

（macOS 会自动加圆角遮罩和投影，逐像素必然对不上）。

### 根因再确认

「.app 不可分发」的根因**不止启动器三个编译期宏**，而是 bundle 里只有启动器 + icns + Info.plist，缺三样东西：

### 嵌入模式设计（daopapers_launcher.c）

**实测踩坑**：`_NSGetExecutablePath(NULL, &sz)` 第一次传 NULL 探测大小时**返回值必然非 0（不是失败）**——把非 0 当失败处理导致嵌入模式永不触发，冒烟时解压出的 bundle 全部回落 development。首次冒烟即抓出。

1. **图源池耗尽 → 旧图循环**：日志反复出现「候选都已看过，改在旧图里循环」；bing 源每天仅 8 张，经屏蔽词过滤后可用池更小，几天后全部看过开始在旧图打转，甚至重复（10-27 09:00 与 10-28 14:03 同一张「秋叶缤纷的池杉林」）。
2. **launchd 语义缺陷**：plist 用 `/usr/bin/open -a` 启动（open 是瞬时命令，KeepAlive 管不到应用进程）且 `KeepAlive=false` → 用户退出应用后彻底停摆，无自愈。用户 10-28 14:03 后退出，今晚 20:00 的换壁纸因此错过。

**修复**：install.sh 的 write_plist 改为直接启动 bundle 内二进制 + `KeepAlive {SuccessfulExit: false}`（崩溃/被杀自动拉起，主动退出 exit 0 不打扰）；本机 plist 已同步重写。**本机 shell bootstrap 持续报 error 5**（受限 shell 无 GUI bootstrap 命名空间，install.sh 早已留档该现象），应用已用 `open -a` 立即拉起（PID 53953，22:12 启动自检通过）；agent 将在下次登录时自动加载新 plist，用户可手动 bootstrap 立即生效。

**遗留**：① 图源池扩大方案待用户决策（Unsplash/Wallhaven key 或启用本地文件夹源）；② 当前 shell 无法 bootstrap，需用户在终端执行一次（下次登录也会自动生效）。
